# 中秋碰面准备

> 用途：张宝文与摩兽线下碰面（2026-09-25 前后）的议程、七类必问问题，以及每个问题的答案会影响哪个决策。读者：张宝文；集成工程师据此准备材料。
> 假设：碰面约 2 小时；对方到场的有 Kim（海外社媒运营）、至少一位销售负责人，最好有一位能拍板账号与付款的领导【待客户确认】。

## 1. 碰面要达成的四个结果

1. 把三个流程捋一遍并当场记下来：咨询怎么接进来、什么客户算有效、销售怎么接手。
2. 让客户节前启动三件事（第 4 节）。
3. 拿到成本与范围所需的几个关键数字：日均咨询量、国家分布、语种、是否投广告。
4. 确认精简版还是完整版的倾向，以及谁拍板。

## 2. 议程

| 时间 | 环节 | 内容 | 产出 |
|---|---|---|---|
| 10 分钟 | 对齐目标 | 用方案书的一页摘要过一遍链路：社媒流量进 WhatsApp，AI 接待与分类，B 端转销售；说明 MVP 验证的是"分类是否有效" | 对目标无异议 |
| 25 分钟 | 流程一：咨询怎么接进来 | 第 3 节问题组 1、2、3 | 渠道清单、号码现状、认证主体 |
| 25 分钟 | 流程二：什么客户算有效 | 问题组 5、6 | 有效线索标准初稿、AI 能说与不能说的清单 |
| 25 分钟 | 流程三：销售怎么接手 | 问题组 4；过一遍销售接手 SOP 的五步 | 接线索的人、协作工具、工作时间、周末安排 |
| 15 分钟 | 上线后谁维护 | 问题组 7；说明日常维护是运营的活，改集成才需要技术 | 知识库负责人与审核人 |
| 15 分钟 | 账号与费用结构 | 官方接入的两种方式；10/1 起客服消息按条计费，每号码每月前 1,000 条免费已由 Meta 官方确认、可以对客户讲（SOURCES S-M1、S-M3）；总包加第三方费用另算加维护另报；两档配置的差别 | 档位倾向；谁拍板；金额由张宝文现场掌握 |
| 5 分钟 | 节前三件事与下一步 | 第 4 节 | 每件事的负责人与日期 |

带去的材料：方案书、报价单、客户需提供清单（均在 `00-client/`）；本文件的问题清单打印一份用于记录。

## 3. 七类必问问题

每个问题后面写明"答案影响什么决策"。答不上来的当场记为待办，指定负责人与日期。

### 问题组 1：咨询量与市场

| 问题 | 答案影响什么决策 |
|---|---|
| 现在各渠道每天大约收到多少咨询？旺季或活动期的峰值是多少？ | 成本模型的日均咨询量，决定第三方月费落在哪一档；Botmaker 套餐与超量；销售值班人手 |
| 咨询主要来自哪五个国家，各占多少？ | 消息费与国家强相关（德国单价是巴西的约 8 倍，SOURCES S-M4），国家分布变了，成本可能差一倍以上；也决定先测哪些语种 |
| 客户用哪些语言来问？团队能审校哪些语言的话术？ | 精简版与完整版的语种范围；固定话术翻译由谁确认 |
| B 端与 C 端咨询大约什么比例？ | 成本模型的 B 端占比；评测集中 B 端样本是否够 30 条；销售通知量 |

### 问题组 2：流量来源与是否投 Click-to-WhatsApp 广告

| 问题 | 答案影响什么决策 |
|---|---|
| 目前运营哪些社媒账号与官网入口？各入口现在引导客户去哪里？ | 来源追踪的短码清单与链接生成表（`01-design/source-tracking.md`）；上线灰度先换哪个入口 |
| Botmaker 有一种省消息费的做法：客户在 WhatsApp 发来消息后只回一条邀请，把客户引到 Botmaker 自家的网页聊天（Central）继续聊。能否接受客户被引导离开 WhatsApp？（本方案默认不接受，全程在 WhatsApp 上接待） | Botmaker 10/1 起在每条线路上默认开启这项转接（SOURCES S-B16）；按默认不接受，配置时逐条线路关闭；若接受，消息费只剩那条邀请消息，但对话与销售接手都转到 Central，销售接手 SOP 与成本模型要重做 |
| 有没有在投、或计划投 Meta 广告？能否改成 Click-to-WhatsApp 形式？ | 广告带来的会话 72 小时内消息免费（SOURCES S-M1），是最直接的降本手段；成本模型的广告入口占比 |
| 谁负责改各入口的链接？ | RACI；灰度上线的执行人 |

### 问题组 3：现有号码与 Meta 账户状况

| 问题 | 答案影响什么决策 |
|---|---|
| 现在业务上用的 WhatsApp 是哪种：普通版、Business App，还是已经接过 API？号码是哪个国家的，手机在谁手里，号码登记在谁名下？ | 号码策略选 a（新办专用号）还是 b（Coexistence），见 `01-design/adr/0002-number-strategy.md`；Coexistence 要求 App 版本 2.24.17 及以上、主设备约每 14 天要打开一次（SOURCES S-M6）；国家限制已取消，只有中国大陆 +86 号码要在接入流程里实测（S-M7） |
| 这个号码上有多少需要保留的老客户与历史聊天？号码是否已经印在物料、官网、经销商资料上？ | 同上：历史与公开程度是选 b 的主要理由 |
| 公司有没有 Meta 商务账户？管理员是谁？做过商家认证吗？ | 关键路径：没有就要节前新建并提交认证；认证卡住时仍可先上线接待客户主动发来的咨询，但显示名审核通过前聊天顶部不显示公司名（SOURCES S-M8） |
| 用哪个主体做认证：境内公司、香港公司，还是欧洲的公司？营业执照、官网域名、企业邮箱是否一致？ | 认证材料清单；合同与开票主体；隐私合规上谁是数据控制者；模型与平台由谁签约付款 |
| 能否办一张公司名下的国际信用卡用于 Botmaker 与 Meta 的账单？ | 第三方费用客户直付能否落地（Botmaker 只收信用卡或借记卡，SOURCES S-B3）；Meta 要求账户上有支付方式，否则 10/1 起每月免费额度用完后服务消息停投，经 Botmaker 接入时由谁绑定【待核实】（S-M9） |

### 问题组 4：B 端交接人、协作工具与工作时间

| 问题 | 答案影响什么决策 |
|---|---|
| B 端线索交给谁？按国家、语种分人，还是一个人统一接？ | 销售队列设计；通知是否分群 |
| 销售日常用企业微信、飞书还是别的工具？通知发到哪个群？ | 通知适配器选哪一种（`01-design/adr/0005-notification-channel.md`） |
| 销售的工作时间是什么？周末与节假日有没有人能每天看一次线索？ | 对客户话术里的工作时间与跟进时限；响应时限 T1 至 T4；是否依赖模板再触达 |
| 销售所在的办公网络能否稳定打开海外后台？ | Botmaker 坐席界面的可达性（SOURCES S-B15）；不行则要考虑 Coexistence 手机端回复或备选平台 |
| 销售现在怎么记录线索？有没有 CRM 或表格？ | 线索库是否需要同步到现有表格工具；二期 CRM 对接的起点 |

### 问题组 5：有效线索标准与历史数据量

| 问题 | 答案影响什么决策 |
|---|---|
| 销售眼里，什么样的经销商或分销商咨询算"有效"？必须知道哪几项信息才值得跟？哪些情况直接不跟？ | 标注指南里的有效线索标准；B 端"一次问齐"要问哪几项；`b2b_qualified` 的判定条件 |
| 有没有已有独家代理、暂不开放的国家或地区？ | 这类线索的话术与去向；优先级规则 |
| 能导出多少条历史咨询？在哪些工具里？能否在开工日前给到 100 至 200 条？ | 离线评测能否如期开始；验收样本量阈值是否要调整 |
| 谁来参与标注？销售能否抽出半天？ | 标注质量；RACI |

### 问题组 6：AI 能说什么、不能说什么

| 问题 | 答案影响什么决策 |
|---|---|
| 零售价能不能对外说？各国是否不同？经销价是否一律不说？ | 知识库的价格条目；价格守卫话术的触发范围 |
| 质保政策有没有可以原文对外的版本？各国是否不同？ | 知识库的质保条目；没有明确版本时质保问题一律转人工 |
| 各国"去哪里买、去哪里试驾"有没有可公开的经销商名单？ | C 端问答的核心内容；名单缺失则这类问题全部转人工，升级率会超标 |
| 有没有绝对不能谈的话题：竞品对比、交期承诺、认证与上牌？ | system prompt 的禁区清单 |
| 品牌语气有什么要求？ | 话术与 prompt 的语气设定 |
| 媒体、供应商、求职这类来访引到哪里？ | "其他"分支的指引内容 |

### 问题组 7：上线后谁维护、谁审核

| 问题 | 答案影响什么决策 |
|---|---|
| 谁负责更新知识库？谁审核后才能生效？ | 运维手册里的更新与审核流程；培训对象 |
| 谁每周抽查 20 至 30 条对话并反馈误判？ | 调优期能否闭环；验收 C1 |
| 账号的所有者与管理员是谁？有人离职时怎么交接？ | 资产归属与权限清单 |
| 对月度维护服务有没有需求，还是先自己维护、有事再找？ | 维护服务是否一并报；金额【张宝文确认】 |

## 4. 节前请客户启动的三件事

| # | 事项 | 负责人 | 期望完成 | 说明 |
|---|---|---|---|---|
| 1 | 启动 Meta 商家认证 | Kim 一方 | 2026-09-30 前提交 | 整个项目里最不可控的一环；商家认证审核最长 14 个工作日（SOURCES S-M8），Meta 审核不因国庆暂停，材料要在节前交上去 |
| 2 | 整理 100 至 200 条历史咨询 | Kim 一方，销售配合 | 2026-10-09 前 | 真实数据是验证"分类是否有效"的唯一依据；去掉敏感信息后导出即可，格式不限 |
| 3 | 销售写下有效线索标准 | 销售主管 | 2026-10-09 前 | 一页纸：哪几项信息齐了就值得跟，哪些情况不跟；模板在标注指南里 |

## 5. 碰面后 24 小时内要做的

1. 把三个流程的结论整理成一页纪要发给客户确认。
2. 用拿到的数字重跑成本模型（`03-whatsapp/cost_model.py`），更新报价单里的第三方费用表。
3. 把已回答的问题从待决问题清单里划掉，未回答的指定负责人与日期。
4. 确认档位与开工日，更新 `timeline.md`。
