# ADR 0001：平台选择 Botmaker

> 用途：记录"第一阶段用哪个平台承接 WhatsApp 与 AI 接待"的决策与依据。读者：集成工程师、张宝文。
> 状态：已采纳（2026-09-21）。与张宝文已对客户给出的口径一致。

## 背景

- 客户内部没有负责 Agent 搭建和维护的人，上线后要靠普通运营维护。
- 张宝文已对客户说明的路线：第一阶段用 Botmaker（Meta 官方 BSP）加轻量线索库，不建复杂 CRM，不自建 Agent；后期视情况升级。
- 客户给的参考平台页就是 Botmaker。
- MVP 要验证的是分类与筛选效果，不是链路本身；链路越现成越好。

## 决策

第一阶段采用 Botmaker：

1. Meta 官方 WhatsApp BSP，走官方接入（SOURCES S-B1）。
2. Flow、AI Agent、知识库、服务队列、工单、标签、人工接管、webhook、Code Actions、API 都是现成能力（SOURCES S-B2、S-B5、S-B9、S-B10），自写代码只剩一个集成服务。
3. 官方支持 Coexistence（SOURCES S-B4），号码策略的两条官方路线都走得通。
4. 后续接 Instagram、Messenger 私信不用换平台（SOURCES S-B1）。

账号开在客户名下，客户为所有者，我方为管理员。

## 备选方案

Botmaker 已确认支持 Coexistence，下表只作兜底：当 Botmaker 在试用阶段暴露出无法接受的问题（后台在销售网络下打不开、结算或开票无法落地）时再启用，各列一家，不深入。

| 项 | Botmaker | YCloud | 阿里云 Chat App Message Service |
|---|---|---|---|
| Coexistence | 支持，帮助中心有专文（SOURCES S-B4） | 官网有 Coexistence 说明页（SOURCES 第 3 节问题 1） | 帮助中心有 Coexistence 最佳实践（同上） |
| 中文后台 | 官网与帮助中心为英、西、葡三语，后台语言【待核实】（SOURCES S-B14） | 任务书前提为"有中文后台"，本次未复核【待核实】 | 阿里云控制台，任务书前提为"有中文后台"，本次未复核【待核实】 |
| 内置 AI Agent 与知识库 | 有；按 token 另计费，单价未公开（SOURCES S-B7） | 【待核实】 | 【待核实】 |
| 计价货币 | USD（SOURCES S-B3） | 【待核实】 | 【待核实】 |
| 备注 | 主要市场在拉美，有时差；开票与合同主体【待核实】 | 若内置 AI 能力不足，需要路线 B 式的外部调用承担更多工作 | 国内主体签约与开票可能更顺【待核实】；同上 |

另一个备选是直接在 Cloud API 上自建：张宝文已对客户说明前期不做，仅作对比；MVP 阶段不值得为此投入。

## 影响

正面：

- 搭建快；运营能在后台自己改知识库与话术；人工接管第一版就有。
- 与张宝文对客户的口径一致。

负面与应对：

| 问题 | 应对 |
|---|---|
| 美元计价、信用卡支付、时差、英西葡支持 | 客户直付；问题攒批书面提；必要时用其官方顾问协助搭建的选项 |
| AI 按 token 另计费且单价未知 | 试用期拿到单价；成本模型给区间（`03-whatsapp/cost-model.md`） |
| 销售所在网络可能打不开后台（SOURCES S-B15） | 开工第一周用销售的真实网络实测；退路见 `0002-number-strategy.md` 的 Coexistence 手机端回复 |
| 平台锁定 | prompt、知识库、标签体系、流程说明全部留在仓库；资产在客户名下；线索数据在自己的线索库 |
