# 验收标准

> 用途：MVP 验收的量化标准，是全仓库验收阈值的唯一源头（机器可读版本为同目录 `thresholds.json`，评测报告与一致性检查直接读取它）。读者：张宝文、集成工程师；方案书用通俗表述引用本文件。
> 假设：阈值为集成工程师建议值，**全部需【张宝文确认】**后再写进对客户的承诺；语种范围随报价档位变化。

## 1. 验收分两次

| 节点 | 时间（见 `07-project/timeline.md`） | 验什么 |
|---|---|---|
| 上线验收 | 上线当周 | 第 2、3、4、5 节全部项 |
| 调优结束验收 | 调优期最后一周 | 用上线后真实对话抽样复测第 2 节指标；第 6 节遗留项清零 |

## 2. 离线评测指标（分类质量）

评测集：客户历史咨询经标注后的真实数据，**不少于 150 条**【张宝文确认】，其中 B 端不少于 30 条；标注方法见 `04-eval/labeling-guide.md`。合成数据只用于跑通工具，不计入验收。评测与生产使用同一模型、同一版 prompt。

| # | 指标 | 阈值 | 计算口径 |
|---|---|---|---|
| A1 | B 端召回率（主指标） | ≥ 90%【张宝文确认】 | 标注为 B2B 的样本中，被判为 B2B 的比例。漏掉经销商的代价远高于误判个人，所以召回率优先 |
| A2 | B 端精确率 | ≥ 80%【张宝文确认】 | 被判为 B2B 的样本中，标注确为 B2B 的比例 |
| A3 | 国家准确率 | ≥ 95%【张宝文确认】 | 仅统计有号码前缀的样本；判定国家 = 客户自述国家，没有则取号码国家码 |
| A4 | 产品识别率 | ≥ 85%【张宝文确认】 | 标注了产品的样本中，识别出的产品代码集合与标注完全一致的比例 |
| A5 | 升级率（转人工比例） | ≤ 30%【张宝文确认】 | 被标记需要人工接管的样本比例；B 端字段收集完成后的正常交接也计入 |
| A6 | JSON 解析成功率 | ≥ 98%【张宝文确认】 | 模型输出能被解析并通过字段校验的比例 |

分语种分布、混淆矩阵、每 100 条成本在评测报告中给出，作参考不设阈值。

## 3. 端到端场景（UAT）

| # | 标准 | 阈值 |
|---|---|---|
| B1 | `uat-test-cases.md` 中的 **20 个**端到端场景全部通过 | 20 / 20【张宝文确认】 |
| B2 | 场景覆盖语种 | ≥ 3 个语种（精简版为 2 个）【张宝文确认】 |
| B3 | B 端线索确认到销售收到通知的时延 | ≤ 60 秒【张宝文确认】 |
| B4 | 人工接管全链路：停 AI → 建工单 → 通知销售 → 销售在 Botmaker 用公司号接手 | 演示通过 |
| B5 | 话题收口：与摩兽无关的问题被礼貌拒答并引导回业务 | 场景用例通过 |
| B6 | 不报经销价、不承诺知识库以外的质保条款 | 场景用例通过 |

## 4. 路线 A / B 决策门（开工第 1 周）

在 Botmaker 试用账号内跑 **20 条**样例（`02-botmaker/trial-test-plan.md`）：字段写入变量的成功率 **≥ 95%** 走路线 A（内置 AI Agent 抽取），否则走路线 B（外部固定 JSON 调用）。【张宝文确认】

## 5. 可维护性与交付物

| # | 标准 | 验法 |
|---|---|---|
| C1 | 运营人员能不经技术人员更新知识库 | 运营现场新增 1 条、修改 1 条 FAQ 并验证生效 |
| C2 | 销售能独立完成一次接手与状态回写 | 销售现场演示 |
| C3 | 文档交付：运维手册、销售接手 SOP、培训计划、维护服务说明 | 文件齐备 |
| C4 | 培训交付：运营、销售各一场 | 签到与录屏 |
| C5 | 资产归属：Meta 商务账户、WhatsApp 账户、号码、Botmaker 账号均在客户名下，客户为所有者 | 后台截图 |
| C6 | 反锁定：system prompt、知识库、标签体系、流程说明在仓库中有最新版本 | 仓库检查 |

## 6. 不属于验收范围

- Meta 商家认证与显示名审核的通过时间（由 Meta 决定）。
- 客户未提供素材导致的知识库空缺。
- 第三方平台故障。
- 第二阶段事项（见 `07-project/phase-2-outline.md`）。
