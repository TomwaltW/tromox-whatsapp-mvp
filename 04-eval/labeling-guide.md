# 标注指南与"有效线索标准"模板

> 用途：指导把历史咨询标注成离线评测集，并给销售一张"什么算有效线索"的填写模板；标注结果是验收指标的唯一依据。读者：摩兽运营与销售（标注人）、集成工程师（质检）。
> 假设：标注用 `labeling-template.csv`（表头不可改）；判定规则与 AI 使用的抽取规则一致，源头是 `shared/prompt_blocks/extraction-rules.md`，两者冲突时以该文件为准并告知集成工程师。

## 1. 要交付什么

| 项 | 要求 |
|---|---|
| 数量 | 真实咨询不少于 150 条，其中 B 端不少于 30 条【张宝文确认】；B 端不足时宁可多翻历史记录补齐，也不要用编造的样本凑数 |
| 覆盖 | 主要语种都要有；刻意保留"难判"的样本（数量不多不少的采购、自称开店但只问零售价、供应商推销等） |
| 粒度 | 一位客户的一次咨询 = 一行 |
| 来源标记 | 真实数据 `data_origin` 填 `real`；`example` 是模板示例行，会被工具跳过；`synthetic` 仅用于仓库自带的合成集 |
| 存放 | 只放在 `04-eval/data/`（已被 git 忽略），不进仓库、不外发 |

## 2. 从聊天记录到一行数据

1. 只取**客户说的话**，按时间顺序用 ` || ` 连接，填入 `conversation_text`；销售和机器人的回复不要。
2. 保留原文语言，不翻译、不润色、不改错别字。
3. 客户首条消息里的来源短码（如 `[IG-2609]`）原样保留，工具会自动处理。
4. 一位客户隔了很久再来、问的是另一件事，拆成两行，`sample_id` 不同、号码相同。
5. 一次咨询超过约 10 条客户消息时，取到"客户身份与诉求已经清楚"为止。

## 3. 隐私处理（标注前完成）

| 内容 | 处理 |
|---|---|
| 客户号码 | 保留（国家判定规则要用）；文件仅限项目成员访问 |
| 正文里的邮箱、电话、地址、证件号、订单号、车架号 | 替换为 `<email>`、`<phone>`、`<address>`、`<id>` |
| 个人姓名 | 替换为同语种的虚构姓名（不要删成空白，否则"是否留下联系人"无法判断） |
| 公司名、门店名 | 保留（属于经营信息，也是判断 B 端的关键线索） |
| 图片、语音、文件 | 不导出；如内容关键，在 `label_notes` 里用一句话说明 |
| 保留期限 | 验收结束后按客户制度删除或归档【待客户确认】 |

历史记录里有欧盟等地区居民的个人信息，导出与使用前请按 `03-whatsapp/compliance.md` 的要求确认合规依据【待客户确认】。

## 4. 逐列标注规则

| 列 | 怎么填 | 谁填 |
|---|---|---|
| `sample_id` | 唯一编号，建议 `R-001` 起 | 运营 |
| `data_origin` | `real` | 运营 |
| `phone` | 客户 WhatsApp 号码，带国家码；`+4917612345678` 或 `4917612345678` 均可；确实没有就留空 | 运营 |
| `conversation_text` | 见第 2 节 | 运营 |
| `language` | 客户首条消息的语言，ISO 639-1 小写：`en`、`es`、`de`、`fr`、`pt`、`it` 等；只有表情或无法判断填 `und` | 运营 |
| `segment` | `B2B` / `B2C` / `unknown`，见 5.1 | 销售复核 |
| `b2b_type` | 仅 B2B 填：`dealer` / `distributor` / `fleet` / `importer` / `other`，见 5.2 | 销售复核 |
| `b2c_intent` | 仅 B2C 填：`buy` / `support` / `parts` / `warranty` / `test_ride` / `other`，见 5.3 | 运营 |
| `country_gold` | 客户真实所在国家或目标市场，ISO 3166-1 两位大写，见 5.4 | 运营 |
| `product_interest` | 客户点名的车型，用产品代码、分号分隔：`MC10;UKKO`；代码目录 `MC10`、`UKKO`、`M05`、`MINO`、`M03`、`PESGO`【待客户确认】；没点名留空 | 运营 |
| `escalation_flag` | 这条咨询是否应当转人工：`true` / `false`，见 5.5 | 销售复核 |
| `escalation_reason` | `escalation_flag=true` 时必填，六选一，见 5.5；否则留空 | 销售复核 |
| `is_valid_lead` | 按第 7 节的标准，销售判断是否有效线索：`yes` / `no` / 留空（拿不准） | 销售 |
| `annotator` | 标注人 | 各自 |
| `label_notes` | 难判的理由、两人分歧的结论、被遮蔽的关键信息 | 各自 |

工具会校验：B2B 行必须有 `b2b_type`；B2C 行必须有 `b2c_intent`；两者不能同时填；`escalation_flag` 与 `escalation_reason` 必须成对；产品代码必须在目录内；号码必须是合法格式。

## 5. 判定细则

### 5.1 segment（B 端、C 端、未知）

| 标 | 典型情形 |
|---|---|
| `B2B` | 代表或打算开办一家会转售、进口、出租或运营摩兽车辆的企业：经销商、分销商、进口商、车队/租赁/配送运营方、店主、采购代理。信号词：dealer、distributor、reseller、wholesale、importer、MOQ、price list、exclusive、container、our shop/company、fleet、rental、公司名、企业官网、数量明显超过 2 台 |
| `B2C` | 个人车主或潜在买家：问零售价、哪里买一台、试驾、自用参数、售后、自己车的配件或质保 |
| `unknown` | 只有问候、看不出来意、垃圾消息、求职、向摩兽推销的供应商、媒体与达人合作、与摩兽无关 |

客户按过按钮的以按钮为准，除非文字明显矛盾（按了 "Rider or Customer" 却写"我有三家店想做分销"），此时以文字为准。

### 5.2 b2b_type

| 取值 | 判定 |
|---|---|
| `dealer` | 零售门店，想在某个城市或区域卖给终端客户 |
| `distributor` | 想做区域或全国分销、发展二级经销商、谈独家 |
| `importer` | 谈进口、整柜、认证（homologation）、清关 |
| `fleet` | 租赁、共享、配送、企业或政府车队采购 |
| `other` | 是 B 端但不属于以上：OEM/ODM、企业礼品、纯线上转售等 |

### 5.3 b2c_intent

| 取值 | 判定 |
|---|---|
| `buy` | 价格、有没有货、颜色与配置可选项、哪里买、分期 |
| `test_ride` | 想看车、试驾、找门店 |
| `support` | 怎么用、App、充电操作、**故障排查类提问**（"充不满怎么办""有异响正常吗"）、说明书 |
| `parts` | 买配件、耗材、备用电池、充电器 |
| `warranty` | 询问质保范围；**明确要求保修维修、更换、退款**；以及安全事故（冒烟、起火、刹车失灵、受伤）。后两类同时要升级，见 5.5 |
| `other` | 以上都不是：驾照与法规、车友活动、新品计划等 |

`support` 与 `warranty` 的分界：客户在问"怎么解决"标 `support`；客户在主张"这该由你们负责"或已发生安全事故标 `warranty`。

### 5.4 country_gold

1. 填**真实**国家或目标市场，不是照抄号码国家码：客户说"我们想把摩兽引进智利"而号码是西班牙的，填 `CL`。
2. 客户没说国家、只提到城市，标注员可以凭常识判断（"慕尼黑"填 `DE`）；拿不准就填号码国家并在 `label_notes` 注明。
3. 这一列用来检验"客户自述国家优先、号码国家码兜底"这条规则在真实世界里有多准，所以要如实填，哪怕规则会判错。

### 5.5 是否转人工与原因

命中多条时取**排在最前**的一条：

| 顺序 | `escalation_reason` | 判定 |
|---|---|---|
| 1 | `complaint_warranty_legal_safety` | 投诉、事故、受伤、电池冒烟起火、法律威胁、退款纠纷、质保索赔或争议、个人数据请求 |
| 2 | `human_requested` | 明确要真人、销售、客服或电话联系 |
| 3 | `price_negotiation` | 要折扣、经销价或批发价、报价单、付款条件、独家条款 |
| 4 | `not_understood_twice` | 机器人连续两次没听懂（只出现在多轮对话里，单条历史咨询一般不用） |
| 5 | `low_confidence` | B 端还是 C 端确实判断不了（见第 6 节），需要人来确认 |
| 6 | `b2b_qualified` | 是 B 端，且类型、对方是谁（公司名或联系人）、市场三项都已知，可以交给销售 |

都不命中填 `false`。单纯问零售价不算 `price_negotiation`；只问"质保多久、保不保电池"不算索赔，不升级。

## 6. 两类错误的代价不对称

| 错误 | 后果 | 代价 |
|---|---|---|
| 把经销商判成个人（漏判） | 销售永远看不到这条线索，客户在机器人那里问了几句就走了 | 高：可能损失一个市场的渠道 |
| 把个人判成经销商（误判） | 销售多看一条，花一两分钟确认后转回 | 低 |

因此：

1. 评测的**主指标是 B 端召回率**（阈值见 `06-acceptance/acceptance-criteria.md`），精确率要求低于召回率。
2. 标注时，B 端还是 C 端**确实两可**的样本一律标 `B2B`（`b2b_type` 选最接近的，拿不准用 `other`），`escalation_flag=true`、`escalation_reason=low_confidence`，并在 `label_notes` 写明"歧义"及理由。AI 的规则与此一致：拿不准时判 B2B 并降低置信度，交给人确认。
3. "两可"不是"信息少"：只有一句问候是明确的 `unknown`，不要标成 B2B。

## 7. "有效线索标准"模板（销售填写）

请销售负责人在中秋碰面前后填好；`is_valid_lead` 一列按此判断，第二阶段的经销商评分也以此为起点。表中"摩兽的标准"一列全部【待客户确认】。

| 维度 | 要回答的问题 | 摩兽的标准 |
|---|---|---|
| 主体 | 哪些类型算有效：门店、分销商、进口商、车队/租赁、线上转售、企业团购？哪些不算？ | 【待客户确认】 |
| 市场 | 重点国家与区域；已有独家代理、暂不开放的国家 | 【待客户确认】 |
| 经营基础 | 是否要求已有实体门店或团队、经营年限（官网对外写的是希望申请方已有至少 1 年的既有架构） | 【待客户确认】 |
| 现有业务 | 是否要求有两轮或电动车经验；在售竞品是否影响判断 | 【待客户确认】 |
| 采购规模 | 首单与年采购量的最低预期；低于多少按个人或团购处理 | 【待客户确认】 |
| 资质能力 | 进口、认证、售后维修能力是否为必要条件 | 【待客户确认】 |
| 联系人 | 需要对方提供哪些信息才值得销售跟进：公司名、职位、官网、邮箱等 | 【待客户确认】 |
| 直接排除 | 明确不跟进的情形：个人代购、只要样车、要求寄售等 | 【待客户确认】 |
| 优先级 | 什么样的线索要当天处理 | 【待客户确认】 |

## 8. 双人标注与分歧处理

1. 分工：运营先标全部样本；销售复核所有 `segment=B2B` 的行、所有 `escalation_flag=true` 的行，以及运营在 `label_notes` 里打了问号的行。
2. 抽检：另取不少于 30 条（或总量的 20%，取大者）由第二人独立重标，不看第一人的结果。
3. 对比 `segment` 与 `escalation_flag` 两列：一致率低于 90% 说明规则理解不一致，先对齐口径、修订本指南，再重标分歧集中的类型。
4. 分歧样本由销售负责人裁决，结论与理由写进 `label_notes`；裁决结果反过来补充到第 9 节的疑难案例。
5. 标注定稿后不再为了"让指标好看"改标签；确需修改，在 `label_notes` 记录日期与原因。

## 9. 疑难案例

| 客户原话（示意） | 标法 | 理由 |
|---|---|---|
| "想买三四台，能发些资料吗" | `B2B` / `other`，升级 `low_confidence` | 数量不上不下，用途不明，按不对称原则 |
| "我开了两家店，把经销价目表发我" | `B2B` / `dealer`，升级 `price_negotiation` | 要经销价，优先级高于"字段已齐" |
| "给自己和太太各买一台，有货吗" | `B2C` / `buy`，不升级 | 明确自用 |
| "我们生产电池组，想成为你们的供应商" | `unknown`，不升级 | 是来推销的，不是客户 |
| "我有 8 万粉丝，想合作" | `unknown`，不升级 | 媒体与达人合作不属于销售线索；转给谁由运营规则决定 |
| "屏幕坏了，我要走保修" | `B2C` / `warranty`，升级 `complaint_warranty_legal_safety` | 明确提出索赔 |
| "质保包含电池吗" | `B2C` / `warranty`，不升级 | 只是询问范围 |
| "充电时电池冒烟了" | `B2C` / `warranty`，升级 `complaint_warranty_legal_safety` | 安全事故 |
| "我不想跟机器人说话"（别的什么都没说） | `unknown`，升级 `human_requested` | 类型未知，但明确要真人 |
| "我在迪拜运营 120 人的配送车队" | `B2B` / `fleet`，`country_gold` 填 `AE` | 只说了城市，国家由标注员如实填写 |

## 10. 交付前自检

```bash
cd 04-eval
python -m eval.run --input data/labeled-v1.csv --prompt prompts/classify-v1.md --model mock --out data/format-check.md
```

能跑完说明格式合格；报错时按提示的行号逐条修正。随后核对：真实样本数与 B 端样本数是否达标、各语种是否都有、`label_notes` 里的问号是否都已裁决。
